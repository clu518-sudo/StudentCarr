## Application Development Needs Analysis Prompt

**Purpose:** To help identify and analyze the comprehensive requirements, technology stack, and architectural considerations for developing an application based on your concept.

---

### Prompt Template:

```
I want to develop an application about {USER_DESCRIPTION}. Please provide a comprehensive analysis covering:

## 1. Customer & User Needs Analysis
- Identify all potential user personas and their specific needs
- List core functional requirements users would expect
- Outline key user experience (UX) expectations
- Define critical user pain points this application should solve
- Specify performance requirements (speed, reliability, scalability)
- Detail security and privacy requirements
- Identify accessibility requirements
- List integration needs with other systems/platforms

## 2. Technical Architecture Recommendations
- Suggest appropriate application architecture patterns (e.g., microservices, monolithic, serverless, event-driven)
- Recommend frontend architecture and frameworks
- Recommend backend architecture and frameworks
- Propose database architecture (SQL vs NoSQL, data modeling approach)
- Suggest caching strategies
- Recommend API design patterns (REST, GraphQL, gRPC)
- Propose authentication and authorization architecture
- Suggest deployment architecture (cloud, on-premise, hybrid)

## 3. Technology Stack Suggestions
- **Frontend:** Frameworks, libraries, and tools
- **Backend:** Programming languages, frameworks, and runtime environments
- **Database:** Primary and secondary database options
- **Infrastructure:** Cloud providers, containerization, orchestration
- **DevOps:** CI/CD tools, monitoring, logging solutions
- **Third-party Services:** Payment gateways, analytics, communication APIs

## 4. Scalability & Performance Considerations
- Horizontal vs vertical scaling strategies
- Load balancing approaches
- Caching layers (CDN, application cache, database cache)
- Database optimization strategies
- Asynchronous processing requirements

## 5. Security Architecture
- Data encryption (at rest and in transit)
- Authentication mechanisms
- Authorization and access control
- API security measures
- Compliance requirements (GDPR, HIPAA, etc.)
- Vulnerability protection strategies

## 6. Development Approach
- Recommended development methodology (Agile, Scrum, etc.)
- Suggested MVP (Minimum Viable Product) features
- Phased development roadmap
- Testing strategy (unit, integration, E2E)
- Documentation requirements

## 7. Useful Hints & Best Practices
- Common pitfalls to avoid in this domain
- Industry-specific best practices
- Optimization opportunities
- Future-proofing considerations
- Cost optimization strategies
- Maintenance and support considerations

## 8. Additional Considerations
- Estimated complexity level
- Required team composition and skills
- Approximate development timeline
- Potential technical challenges
- Recommended learning resources
```
